# 分镜绘制页集成豆包网页视频生成

## Context（背景与目标）

**问题**：当前分镜绘制页（[StoryboardDraw.tsx](file:///d:/trae_projects/fivedesigner/src/pages/StoryboardDraw.tsx)）的视频生成只走付费 API 模式（`useVendorGeneration` → `AI.Video.generate` → vendor 沙箱 HTTP 请求），无法利用用户在「页内浏览页」（BrowserManager）已登录的免费豆包网页账号。用户要生成视频必须手动切到页内浏览页，手动上传资产图片、粘贴提示词、点生成，再手动下载——而分镜绘制页这些数据全都有（提示词、首帧/参考图、关联资产）。

**外部插件不可用**：用户提供的 `E:\BaiduNetdiskDownload\...\video_plugin_dola_doubao` 是 Python 插件，依赖**付费的"豆包管理器.exe"(Dola) + 激活码**（[main.py:86-114](file:///E:/BaiduNetdiskDownload/豆包管理器/video_plugin_dola_doubao5/video_plugin_dola_doubao/main.py#L86-L114)），不符合"免费豆包账号"诉求。项目内 `src-tauri/resources/doubao-bridge/bridge.js`（171KB）是该 Dola 桥接脚本的副本，**全项目无任何代码引用**，同样依赖付费 Dola，不可用。

**目标**：复用 BrowserManager 已登录的豆包 WebView，通过 JS 注入自动化操作豆包网页（填提示词、上传图、点发送），复用已有的去水印媒体捕获机制拿回无水印视频，无需付费 API 或外部 Dola 软件。支持**一键批量生成**与**账号配额自动轮换**（每账号约 3 个/周期，用完自动切下一个）。

**已确认的决策**：
1. 在现有 StoryboardDraw.tsx 增加"豆包网页"生成模式（与现有 `generationMode: 'ai' | 'comfyui'` 并列，复用现有提示词/参考图/首帧 UI）
2. 后台运行，可一键切换显示浏览器（默认隐藏，出错时可查看）
3. 参数面板内选豆包账号，配额不足时自动轮换
4. 批量生成走现有 BatchGenerationPanel 的豆包模式分流

## 实现方案

### 1. 账号配额管理（新文件 `src/hooks/useDoubaoQuota.ts`）

**数据结构**：
```ts
interface DoubaoAccountQuota {
  accountId: string
  used: number              // 当前周期已用
  limit: number             // 上限，默认 3
  resetAt: number           // 下次重置 epoch 毫秒
  lastUsedAt: number | null
  updatedAt: number
}
interface DoubaoQuotaConfig {
  defaultLimit: number      // 默认 3
  resetMode: 'daily' | 'manual'  // 默认 daily
  dailyResetHour: number    // 默认 0
  perItemTimeoutMs: number  // 默认 300000（5 分钟）
}
```

**存储**：配额用 `settingsDB.save({ ['doubao_quota_' + accountId]: quotaObj })`，配置用 `settingsDB.save({ doubao_quota_config: config })`，读取用 `settingsDB.getAll()` 筛选 `doubao_quota_` 前缀。账号列表仍用 localStorage `browser_accounts`（不破坏 BrowserManager）。

**重置策略**：`daily` 模式下 `resetAt` = 下一个 `dailyResetHour` 的 epoch；查询时若 `Date.now() >= resetAt` 自动置 `used=0` 并重算。`manual` 模式仅用户手动重置。

**hook 接口**：
```ts
useDoubaoQuota() → {
  quotas, config,
  getAvailableAccount(preferId?): string | null,  // preferId 优先，否则按剩余配额降序
  consume(accountId): void,    // 内存 used+1，不立即落库
  release(accountId): void,    // 失败回滚
  markBroken(accountId): void, // 标记该账号不支持自动上传
  flush(): Promise<void>,      // 批量写回 settingsDB
  resetAccount(accountId): Promise<void>,
}
```
查询用 `useQuery({ queryKey: ['doubao','quotas'] })`，批量生成时内存读写、结束统一 flush。

### 2. 豆包网页自动化脚本（新文件 `src/services/doubao/autoScript.ts`）

**纯函数 TS 文件**，构造 JS 字符串后通过 `evalWebviewJs` 注入。挂载到 `window.__DOUBAO_AUTO__` 命名空间，与去水印脚本的 `__EXTRACTED_MEDIA__` 完全隔离，不 patch fetch/XHR，不重复捕获视频。

**选择器常量**（新文件 `src/services/doubao/selectors.ts`，集中维护便于豆包改版时调整）：
- 提示词框：`[contenteditable="true"][role="textbox"]` / `textarea[placeholder*="发消息"]` / `div[contenteditable="true"]`
- 文件输入：`input[type="file"]`
- 发送按钮：`[data-testid*="send"]` / `button[aria-label*="发送"]` / 含"发送"文本的 button

**三个脚本构造器**：
- `buildAutoScript({ prompt, imageBase64List, submitToken })` → IIFE，执行填词→上传→点发送，推进 `window.__DOUBAO_AUTO_STATUS__ = { phase, ok, msg, submittedAt }`
- `buildPollStatusScript()` → 读 `__DOUBAO_AUTO_STATUS__` 并 `invoke('report_doubao_auto_status', { accountId, status })` 回传
- `buildClearScript()` → 清空 `__EXTRACTED_MEDIA__` + postMessage clear（防止上条视频残留误匹配）

**图片上传兜底链**（脚本内自动降级）：
1. DataTransfer：`new DataTransfer().items.add(file)` → `input.files = dt.files` → dispatch change
2. paste 事件：`new ClipboardEvent('paste', { clipboardData: dt })`
3. 都失败 → `phase='error'`，由 hook 决定切账号或提示用户

File 对象从 base64 构造用 `atob` + `Uint8Array` → `new Blob` → `new File`（**不用 `fetch(data:)`**，避免 CSP 问题，符合项目规范）。

### 4. 单条生成 hook（新文件 `src/hooks/useDoubaoBrowserGeneration.ts`）

**接口兼容 `useVideoGeneration`**（返回本地视频路径），便于 VideoGenNode 无差别替换：
```ts
interface DoubaoBrowserGenerationRequest {
  prompt: string
  firstFrame?: string
  referenceImages?: string[]
  duration?: number
  projectId?: string
  episodeId?: string
  preferAccountId?: string
  onProgress?: (info: { phase: string; accountId: string; msg?: string }) => void
}
useDoubaoBrowserGeneration() → useMutation<string, Error, DoubaoBrowserGenerationRequest>
```

**mutationFn 流程**（内部自动轮换账号）：
```
for (accountId of quota.iterAvailable(preferAccountId)):
  1. 准备资源：firstFrame/referenceImages → imagePathToBase64；生成 submitToken
  2. 确保 WebView 运行：未运行则 createWebview(doubao.com, {cookies,proxy})；运行中则保持后台
  3. 导航到创作页：get_webview_url 检测，非 /chat 则 navigateWebview
  4. 清理残留：evalWebviewJs(buildClearScript())
  5. 注入自动化脚本：evalWebviewJs(buildAutoScript({prompt, imageBase64List, submitToken}))
  6. 轮询状态：周期性 evalWebviewJs(buildPollStatusScript())，listen 'doubao-auto-status'
     等 phase === 'submitted'，记录 submittedAt
  7. 等待视频：listen 'media-extracted'，匹配 accountId && mediaType==='video' && timestamp > submittedAt-2000
     超时 perItemTimeoutMs → throw
  8. 保存：saveMediaFile(noWatermarkUrl, {type:'video', extension:'mp4', projectId, episodeId})
  9. 成功 → quota.consume(accountId); return 本地路径
  catch DoubaoQuotaExhaustedError → continue 轮换
  catch DoubaoUploadUnsupportedError → quota.markBroken(accountId); continue
throw '所有豆包账号均不可用'
```

**结果匹配**：按 `submittedAt` 时序窗口 + accountId 匹配，取第一个匹配视频，`processedTokensRef` 去重。提交前清理 `__EXTRACTED_MEDIA__` 防残留误匹配。

## 风险与兜底

| 风景 | 兜底 |
|---|---|
| 图片上传被豆包拦截（DataTransfer/paste 失败） | Phase 6 CDP `DOM.setFileInputFiles`；仍失败则 toast「账号 X 不支持自动上传，已跳过」并 markBroken 切下一账号 |
| 豆包 DOM 选择器变更 | 选择器集中在 selectors.ts 容错链；每步读回校验（填词后读 textContent 不含 prompt 则报错）；出错 phase='error' 含具体选择器，提示用户点眼睛按钮查看 |
| 生成超时 | perItemTimeoutMs 默认 5 分钟；超时不 consume 配额，标记 item failed，继续下一条 |
| 配额误判（用户网页手动生成消耗了配额） | 配额作乐观预估；hook 识别豆包「配额不足」响应文案 → 抛 DoubaoQuotaExhaustedError 轮换 |
| 视频误匹配（上条残留） | 提交前清理 `__EXTRACTED_MEDIA__`；匹配窗口 `timestamp > submittedAt-2000`；processedTokens 去重 |
| WebView 未登录/Cookie 过期 | 脚本检测 URL 含 login → 抛 DoubaoSessionExpiredError，toast「请到浏览器管理页重新登录」并跳过 |
| CSP 阻止 base64 转 Blob | 用 `atob`+`Uint8Array` 而非 `fetch(data:)`（符合项目 CSP 规范） |
| 多节点并发 | hook 内模块级 Promise 队列串行化同账号；Phase 5 先不并行 |
