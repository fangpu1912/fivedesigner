# 豆包网页视频生成接入任务队列

## Context

当前豆包网页视频生成在 `StoryboardDraw.tsx` 中通过 `useDoubaoBrowserGeneration` hook 的 `mutateAsync` 直接调用，进度靠局部 state `doubaoProgress` 维护，取消/重试只能在页面内操作，且无法离开页面后台运行。用户要求：**把豆包生成接入任务队列系统，在 TaskQueuePanel 里统一管理进度、取消、重试，支持批量生成，浏览器后台隐藏运行**。

核心矛盾：任务队列 executor 是模块级纯函数（`taskQueue.ts` 的 `registerDefaultExecutors`），无法调用 React hook。因此必须把豆包生成的核心逻辑从 hook 抽离成可被 executor 调用的 service。

已验证的关键事实：
- `useEmbeddedBrowser` 的 useEffect cleanup 只断开 ResizeObserver，**不 closeWebview**——StoryboardDraw 卸载不会销毁 webview，后台运行可行。
- `hide_webview` 后 `eval_webview_js` 仍生效（Rust 侧不检查 is_active）——隐藏运行时自动化脚本和轮询正常工作。
- `useDoubaoQuota` 的 consume/getAvailableAccount 是同步操作内存 Map，JS 单线程无竞态；`withAccountLock` 已是模块级 Map。
- StoryboardDraw 的 `handleGenerateComfyUI`（L1068）已用 `addTask` 走队列——豆包照搬此模式。
- `selectedIds` 多选机制（L227）已存在，批量生成有现成基础。

## 关键实现要点

### 1. embeddedBrowserService.ts（新建）
把 `useEmbeddedBrowser.ts` 里的 invoke 调用抽成纯函数。与 hook 版区别：**不 catch 吞错**（让上层 service 感知失败），**不包含 containerRef/position 逻辑**（定位由 hook 负责，需 DOM rect）。函数签名：
- `createWebview(accountId, url, options?)` → invoke('create_embedded_webview')
- `evalWebviewJs(accountId, jsCode)` → invoke('eval_webview_js')，throw 不吞
- `navigateWebview` / `hideWebview` / `showWebview` / `closeWebview` / `injectCookies` / `getWebviewUrl`

### 2. doubaoQuotaService.ts（新建）
把 `useDoubaoQuota.ts` 的 `memQuotasRef`/`memDirtyRef` 提升为模块级 `memQuotas`/`memDirty`，逻辑原样搬运。新增 `subscribe(listener)` + `notifyListeners()` 供 hook 订阅触发重渲染。`load()` 用 `loadingPromise` 守卫防止并发重复加载。复用已导出的纯函数 `getDoubaoAccounts()`（从 localStorage 读）。`flush` 内部的 `queryClient.invalidateQueries` 改用从 `@/providers/QueryProvider` 导入的 `queryClient` 单例。

### 3. doubaoBrowserService.ts（新建）
从 `useDoubaoBrowserGeneration.ts` 搬运：
- `accountLocks` Map + `withAccountLock`（原 L79-L86，原样）
- 4 个错误类（DoubaoUploadUnsupportedError 等）
- `generateWithAccount`（原 L98-L191）：内部 `browser.xxx` → `embeddedBrowserService.xxx`，`quota.xxx` → `doubaoQuotaService.xxx`，`quota.config.perItemTimeoutMs` → `doubaoQuotaService.getConfig().perItemTimeoutMs`
- `waitForSubmitted` / `waitForVideo`（原样，已支持 signal）
- 顶层 `generateVideo(params, signal)`：原 mutationFn 的账号轮换循环逻辑（原 L194-L290）

**重要**：`saveMediaFile` 已在 `generateWithAccount` 内部调用（原 L179），返回值即本地路径，executor **不应再 save**。`signal` 必须透传到 waitForSubmitted/waitForVideo。`listen` 来自 `@tauri-apps/api/event`（非 React），service 可直接 import。

### 4. taskQueue.ts - doubao executor
在 `registerDefaultExecutors` 末尾追加（参照 batch_operation executor L282-L534 的写法）：
```typescript
registerExecutor('doubao_video_generation', async (task, updateProgress, signal) => {
  const { doubaoBrowserService } = await import('@/services/doubaoBrowserService')
  const { storyboardDB } = await import('@/db')
  const { prompt, firstFrame, lastFrame, referenceImages, aspectRatio,
          projectId, episodeId, preferAccountId, itemId, itemType } = task.metadata as {...}

  // phase -> progress 映射
  const PHASE_PROGRESS = { starting:5, navigating:10, filling:20, uploading:30,
                           submitting:40, submitted:50, detecting:60, saving:90 }
  const onProgress = ({ phase, msg }) => {
    if (phase === 'error') return  // 错误由抛错处理，不更新 progress
    updateProgress(PHASE_PROGRESS[phase] ?? 50, msg || phase)
  }

  if (signal?.aborted) return { success: false, error: '已取消' }

  const savedPath = await doubaoBrowserService.generateVideo(
    { prompt, firstFrame, lastFrame, referenceImages, aspectRatio,
      projectId, episodeId, preferAccountId, onProgress }, signal
  )

  if (signal?.aborted) return { success: false, error: '已取消' }

  // 落库（仅 storyboard 类型，参照 batch_operation L347-L355）
  let dbUpdateFailed = false
  if (itemType === 'storyboard' && itemId) {
    try {
      await storyboardDB.update(itemId, { video: savedPath, status: 'completed' })
      queryClient.invalidateQueries({ queryKey: ['storyboards', episodeId] })
    } catch { dbUpdateFailed = true }  // 视频已生成，不因落库失败而重试浪费配额
  }

  updateProgress(100, '完成')
  return { success: true, outputPath: savedPath, outputUrl: savedPath,
           data: { savedPath, itemId, dbUpdateFailed } }
})
```
service 抛错时 executor 直接 throw，taskQueue 自动 catch 标记 failed + errorMessage（"肖像保护"等豆包原始错误透传）。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| service 化后 hook 与 service 内存不一致 | service 是唯一数据源，hook 通过 subscribe+forceUpdate 同步；禁止 hook 自维护 memQuotasRef |
| 重复 addTask 同一分镜 | 按钮 disabled 判断该 itemId 是否有 pending/running 任务 |
| saveMediaFile 阶段未监听 signal | 下载通常几秒，可接受；可在 saveMediaFile 前加 `if(signal?.aborted) throw` 守卫 |
| storyboardDB.update 失败但视频已生成 | task 标记 completed，data 加 dbUpdateFailed:true，不重试（避免浪费配额） |
| webview 跨页面存活内存 | 后台运行的前提，保持现状；Tauri 进程退出自动回收 |
| 批量配额耗尽 | getAvailableAccount 已实现自动轮换；全部耗尽则 executor 抛错，任务 failed 提示"所有豆包账号均不可用" |
